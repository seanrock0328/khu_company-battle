# 10자 사원 주식회사

2026 KHU AI Challenge 출품작. 직급별 글자 수로 직원을 만들어 회사를 운영하는 AI 텍스트 배틀 게임입니다.

**한 명씩 혼자 플레이하고, 1년(4분기) 누적 수익으로 순위를 겨룹니다. 기본 순위표는 업종과 관계없이 하나이며, 같은 업종 대결은 선택 기능입니다.**

**게임 흐름**
1. **창업**: 닉네임 → 업종 → 회사 세부정보·이름·사훈 → 자금 출처 선택 → **봉투를 한 번 열어 회사 통장에 입금**
   - 부모님 돈: 8,000만원, 통장이 마이너스가 되면 긴급 용돈 4,000만원을 딱 한 번 지원
   - 알바로 모은 돈: 1억원, 후보 직원들의 시작 충성심 +2
   - 로또 당첨금: 6,000만원·1억원·1억 4,000만원 중 하나. 개봉 후 출처·금액이 고정되고 새로고침·이어하기로 다시 뽑지 않음
2. **ChatKHU**: 회사 세부정보·사훈으로 수익모델(판매·서비스·구독·광고·중개)과 고객 성향을 정하고 창업 화면에서 단가·고객 규모·비용을 공개. 창업 뉴스, 4분기 이벤트(위기 2, 기회 2), 면접 후보 18명의 이름·자기소개·면접 답변
3. **면접**: 임원·부장·차장·과장·대리·사원마다 후보 3명 중 1명 (또는 공석, 단 최소 4명은 채용). 지원 동기·실수 대처·지시 전달 중 질문을 골라 답변을 하나 이상 들은 뒤 채용. 추가 질문은 후보 성격에 따라 게임이 답하며 AI를 별도로 호출하지 않음. 능력·운·MBTI·안정형/회피형 비율은 보이고 정직도는 숨김. 능력이 좋을수록 연봉이 비쌈
4. **분기마다**: 투자 선택 → 100자로 경영 지시 → AI가 지시의 뜻을 해석 → 게임이 직원의 전달·실행과 손익 계산 → AI가 그 결과를 연기 → 보고에서 **실제 행동 고르기** → **🔍 파고들기 / 👏 칭찬하기** → 결산
   - **회사 영업이익 = 실제 수량 × 단가 − 직접 원가 − 고정비 − 지시 실행비 − 급여**. 업무 점수를 돈으로 바꾸지 않음. 광고는 노출 수, 구독은 유료 구독자, 서비스는 완료 계약, 중개는 성사된 거래에서 수입 발생
   - 요금·광고량·홍보·품질·원가 절감·시설 확장을 지시할 수 있음. 할인하면 고객이 늘 수도 있고, 광고를 늘리면 이용자가 떠날 수도 있음. 고객 성향·시장·직원 능력/인원·처리 한도에 따라 계산
   - **충성심 → 전달 확률**, 능력 → 전달 정확도와 처리 한도, 정직도 → 보고의 진실성, 운 → 작은 시장 변동. 지시를 지켰는지와 돈을 벌었는지는 별개
   - **행동 추리 정답 +100만원**. 회사 영업이익과 별도 표시. 칭찬·추궁은 이미 계산한 회사 수익을 바꾸지 않음
   - 지시대로 실행했을 때 칭찬하면 충성심 +1, 파고들면 −1. 다르게 실행했을 때 칭찬하면 그대로, 파고들면 전달을 바로잡아 +1. 충성심 0이면 퇴사
   - **그대로 운영 / 1,000만원 투자**. 회사 영업이익이 양수면 1,600만원 회수, 적자·본전이면 500만원 회수. 급여·고정비·회식비를 남겨야 투자 가능
   - **분기 순이익 = 영업이익 + 판단 보너스 + 투자 회수 − 투자 원금 − 회식비 − 휴업 손실**. 잔액 = 창업자금 + 누적 순이익 + 긴급 용돈. 지원금은 순이익에서 제외
   - 한 분기 실행비는 최대 1,000만원이며 남은 현금을 넘을 수 없음. 개선은 무료가 아니며, 원가 절감은 품질도 낮춤. 요금·품질·시설·고객 유지 효과는 다음 분기로 이어짐
   - 비교를 위해 모든 모델의 초기 기준 매출은 1억원, 직접 원가 비율은 25%, 고정비는 2,500만원. 분기 고객·광고주 예산은 1억 2,500만원. 변화율은 최대 30%, 누적 요금은 시작의 70~180%, 광고량은 50~180%. 제한과 실행비를 화면에서 안내
   - 전원 퇴사 분기는 매출·급여·투자 0원, 임대료·위약금 1억원. 4분기까지 결산. 정상 운영 최대 손실 9,900만원보다 커서 중단으로 손실을 피할 수 없음
   - **사장 필살기: 판당 딱 한 번**. 회식(300만원·충성심 +2), 직통 전화(말단에게 직접 전달, 급여는 전원 지급), 현장 출동(실제 행동·영업이익 확인)
5. **분기·연간 그래프**: 통장 잔액 꺾은선, 수입·지출 막대, 분기별 통장 명세. 매출·급여·원가·실행비·영업이익·판단 보너스·투자·지원금을 구분. 마이너스도 표시
6. **1년 결산**: 최종 잔액과 순이익을 나란히 표시하고 **순위는 순이익으로만 비교**. 거짓말왕·충성심·경영 방식별 엔딩과 결산 복사 기능 제공

**순위표**: 오른쪽 위 🏆 버튼. 게임한 노트북 브라우저에 저장되므로 노트북 한 대로 돌려가며 하세요. 다른 기기에서 같은 업종으로 겨루려면 순위표 화면의 **대결 링크**로 접속합니다. 연습 모드가 섞인 판은 순위에 들어가지 않습니다. ChatKHU 답을 복사·붙여넣기로 넣은 단계가 있는 판도 연습으로 칩니다. 시연 전 테스트 기록은 순위표 맨 아래 **순위표 초기화**(두 번 클릭)로 지우세요. 초기화하면 대결 업종도 새로 뽑습니다.

**로그인**: 공유 저장소가 켜져 있으면 처음 화면이 로그인입니다. 전시회 관람객은 **가입 없이 닉네임만으로 바로 시작**(게스트, 순위표에 `닉네임(손님)`)할 수 있습니다. 아이디가 곧 닉네임이라 겹치지 않고(대소문자 무시), 하던 게임은 어느 기기에서든 이어서 할 수 있습니다(`js/account.js`). 순위 기록은 로그인한 아이디로만 저장됩니다. 로그인한 채로 1년 결산이 끝나면 **로그아웃하고 다음 사람**(기본)과 **같은 아이디로 한 판 더**를 고를 수 있어, 다음 관람객의 기록이 앞사람 이름으로 올라가지 않습니다. 저장된 게임을 서버에서 잠깐 못 불러오면 새 게임으로 넘어가지 않고 **다시 시도**를 보여 줍니다.

**공유 순위표**: 팀 서버에 저장소(KV)를 연결하면 모든 기기가 순위표 하나와 대결 업종 하나를 같이 씁니다(`js/board-sync.js`). 연결 전이나 서버 오류 때는 각 기기에 저장합니다. 초기화에는 관리자 코드가 필요합니다. 설정법은 [`docs/cloudflare-setup.md`](docs/cloudflare-setup.md) 아래쪽.

기본 순위는 **모든 업종**을 함께 표시하며, 4분기를 모두 결산한 판만 기록합니다. 팀 서버 공유 저장소가 켜져 있으면 모든 기기의 기록이 한 순위표에 모이고, 꺼져 있으면 각 기기에만 저장됩니다(이때 공유 링크는 업종을 맞추는 용도). 다른 업종 링크로 바꾸어도 기존 업종의 기록은 보관됩니다.

이전 경제 규칙의 기록은 보관하되 새 사업 수익 규칙(v7 로컬 키, 공유 뉴스 접두어 `사업 수익 v2 · `)과 분리합니다. 기존 규칙으로 저장된 게임은 이어하기 화면에서 안내 후 새로 시작합니다. 로그인한 사용자의 봉투 금액·면접·사업모델·투자·필살기·지시 초안·실행 주사위·추리 선택지는 기기 내 즉시 보관하고, 서버에는 무료 저장 한도를 아끼려고 모아서 저장해 이어하기에 반영합니다(봉투 개봉·보고 받음·결산은 몇 초 안에, 면접·지시 쓰기는 손을 멈추면 20초 뒤, 길어도 1분 안에). 게스트는 기존처럼 이어하기를 지원하지 않습니다.

규칙을 수정한 뒤에는 `node --test`로 사업모델·할인/광고 반응·행동 보너스(`tests/economy.test.js`), 면접·칭찬/추궁·퇴사·순위표(`tests/game.test.js`)와 팀 서버·저장(`tests/server.test.js`)을 한 번에 확인할 수 있습니다. 진짜 팀 서버와 ChatKHU는 부르지 않습니다. Node.js 기본 기능만 사용하며 게임 실행에는 필요하지 않습니다.

**ChatKHU 연결**: 팀 중간 서버(Cloudflare Worker)가 팀 키로 ChatKHU를 대신 불러서, 플레이어와 심사위원은 키 없이 플레이합니다. 설정법은 [`docs/cloudflare-setup.md`](docs/cloudflare-setup.md). 팀원이 자기 키로 테스트하려면 오른쪽 위 🔌 버튼에서 개인 키를 넣으면 됩니다.

ChatKHU 쓰는 법은 [`prompts/chatkhu.md`](prompts/chatkhu.md)에 있습니다.

### 2. GitHub Desktop 설치

명령어 없이 버튼으로 쓰는 프로그램입니다. [desktop.github.com](https://desktop.github.com)에서 설치하고 GitHub 계정으로 로그인합니다.

### 3. 저장소 만들기 (팀장 한 명만)

1. GitHub 웹사이트 오른쪽 위 **+** → **New repository**

3. **Create repository**
4. GitHub Desktop에서 **File → Add local repository**로 이 폴더를 고르고, "create a repository" 안내가 나오면 따라서 만든 뒤 **Publish repository**

### 4. 저장소 받기 (나머지 3명)

1. 메일로 온 초대를 **수락**
2. GitHub Desktop → **File → Clone repository** → `khu-company-battle` 선택 → **Clone**

이제 내 컴퓨터에 폴더가 생겼습니다. 이 폴더에서 작업합니다.

## 매번: 작업 순서 (이것만 기억하세요)

```
① 받기 (Pull)  →  ② 작업  →  ③ 기록 (Commit)  →  ④ 올리기 (Push)
```

### ① 받기: 작업 시작 전에 무조건

GitHub Desktop 위쪽 **Fetch origin** → **Pull origin**이 나오면 누르기.
다른 사람이 올린 최신 코드를 받아옵니다.

### ② 작업

VS Code 등으로 **자기 담당 파일만** 고칩니다.
`index.html`을 브라우저로 열어서 잘 되는지 확인합니다.
(파일을 직접 열면 팀 서버의 자동 ChatKHU·로그인은 기본으로 꺼져 있습니다. 켜는 법은 [docs/cloudflare-setup.md](docs/cloudflare-setup.md)의 "index.html 파일을 직접 열어 테스트할 때")

### ③ 기록 (Commit)

GitHub Desktop 왼쪽에 바뀐 파일이 보입니다.
왼쪽 아래 **Summary**에 무엇을 했는지 한 줄 쓰고 **Commit to main**.

좋은 예: `채용 화면에 예산 막대 추가` · 나쁜 예: `수정`

### ④ 올리기 (Push)

위쪽 **Push origin** 클릭. 이제 팀원들이 받을 수 있습니다.

> **작게 자주 올리세요.** 1~2시간마다 한 번. 하루 모아서 올리면 충돌이 커집니다.

## 문제가 생겼을 때

### Push가 안 되고 "Pull 먼저 하라"고 할 때

다른 사람이 먼저 올린 것입니다. **Pull origin**을 누른 뒤 다시 **Push origin**.

### 충돌(conflict)이 났을 때

같은 파일의 같은 부분을 두 사람이 고친 것입니다.

1. 당황하지 말고 단톡방에 알리기
2. 파일을 열면 이런 표시가 있습니다.
   ```
      내가 쓴 내용
   
   팀원이 쓴 내용
      ```
3. 둘 중 맞는 것만 남기고 `<<<<<<<`, `=======`, `>>>>>>>` 줄을 모두 지운 뒤 저장
4. GitHub Desktop에서 Commit → Push

### 망한 것 같을 때

**절대 폴더를 지우고 새로 받지 마세요.** 올리지 않은 작업이 사라집니다. 먼저 단톡방에 화면 캡처를 올리세요.
