# 10자 사원 주식회사

2026 KHU AI Challenge 출품작. 직급별 글자 수로 직원을 만들어 회사를 운영하는 AI 텍스트 배틀 게임입니다.

**한 명씩 혼자 플레이하고, 2년(8분기) 누적 수익으로 순위를 겨룹니다. 같은 대결의 사장님들은 모두 같은 업종입니다.**

**게임 흐름**
1. **창업**: 닉네임 → 대결 업종(대결의 첫 사람이 ChatKHU로 뽑고, 다음 사람부터는 같은 업종) → 무슨 일을 하는 회사인지 직접 적기 → 회사 이름, 사훈, 창업 자금(예산 18/22/28)
2. **ChatKHU**: 창업 뉴스, 8분기 이벤트(위기 5, 기회 3), 면접 후보 18명의 이름·자기소개·면접 답변
3. **면접**: 임원·부장·차장·과장·대리·사원마다 후보 3명 중 1명 (또는 공석). 지원 동기·실수 대처·지시 전달 중 질문을 골라 답변을 하나 이상 들은 뒤 채용. 추가 질문은 후보 성격에 따라 게임이 답하며 AI를 별도로 호출하지 않음. 능력·운·MBTI·안정형/회피형 비율은 보이고 정직도는 숨김. 능력이 좋을수록 연봉이 비쌈
4. **분기마다**: 사장이 100자로 지시 → ChatKHU가 직원들을 연기(말 바꾸기, 거짓말, 보고 부풀리기) → 부풀려진 보고를 받고 **🔍 파고들기 / 👏 칭찬하기** 선택 → 진실 공개(🤥) → 분기 수익
   - 칭찬 + 잘함 → 충성심 +1 · 칭찬 + 못함 → 불이익 −3,000만원
   - 파고듦 + 잘함 → 충성심 −1 (0이면 퇴사) · 파고듦 + 못함 → 불이익 없음
   - 분기 수익 = 성과 점수 × 100만원 − 연봉 합 × 200만원 − 불이익 (성과 60점 이상이 "잘함")
   - 전원 퇴사해도 8분기까지 진행. 남은 분기는 매출·인건비 0원에 **임대료·위약금으로 분기마다 −9,000만원**, AI 호출 없이 결산. 정상 경영의 최대 분기 손실(8,600만원)보다 커서 전원 퇴사로 적자를 피할 수 없음
5. **2년 결산**: 누적 수익, 같은 업종 순위, 거짓말왕, 직원들의 진짜 정직도와 충성심

**순위표**: 오른쪽 위 🏆 버튼. 게임한 노트북 브라우저에 저장되므로 노트북 한 대로 돌려가며 하세요. 다른 기기에서 같은 업종으로 겨루려면 순위표 화면의 **대결 링크**로 접속합니다. 연습 모드가 섞인 판은 순위에 들어가지 않습니다. 시연 전 테스트 기록은 순위표 맨 아래 **순위표 초기화**(두 번 클릭)로 지우세요. 초기화하면 대결 업종도 새로 뽑습니다.

순위는 **현재 대결과 같은 업종**끼리 표시하며, 8분기를 모두 결산한 판만 기록합니다. 공유 링크는 업종을 맞추는 용도이고 **다른 기기의 기록을 자동으로 합산하지는 않습니다**. 다른 업종 링크로 바꾸어도 기존 업종의 기록은 보관됩니다.

규칙을 수정한 뒤에는 `node --test tests/game.test.js`로 면접·칭찬/추궁·퇴사·순위표를 확인할 수 있습니다. Node.js 기본 기능만 사용하며 게임 실행에는 필요하지 않습니다.

**ChatKHU 연결**: 팀 중간 서버(Cloudflare Worker)가 팀 키로 ChatKHU를 대신 불러서, 플레이어와 심사위원은 키 없이 플레이합니다. 설정법은 [`docs/cloudflare-setup.md`](docs/cloudflare-setup.md). 팀원이 자기 키로 테스트하려면 오른쪽 위 🔌 버튼에서 개인 키를 넣으면 됩니다.

ChatKHU 쓰는 법은 [`prompts/chatkhu.md`](prompts/chatkhu.md)에 있습니다.

### 2. GitHub Desktop 설치

### 3. 저장소 만들기 (팀장 한 명만)

1. 메일로 온 초대를 **수락**
2. GitHub Desktop → **File → Clone repository** → `khu-company-battle` 선택 → **Clone**

## 매번: 작업 순서 (이것만 기억하세요)

```
① 받기 (Pull)  →  ② 작업  →  ③ 기록 (Commit)  →  ④ 올리기 (Push)
```

### ① 받기: 작업 시작 전에 무조건

GitHub Desktop 위쪽 **Fetch origin** → **Pull origin**이 나오면 누르기.
다른 사람이 올린 최신 코드를 받아옵니다.

### ② 작업

VS Code 등으로 **자기 담당 파일만** 고칩니다.
`index.html`을 브라우저로 열어서 잘 되는지 확인합니다.

### ③ 기록 (Commit)

GitHub Desktop 왼쪽에 바뀐 파일이 보입니다.
왼쪽 아래 **Summary**에 무엇을 했는지 한 줄 쓰고 **Commit to main**.

좋은 예: `채용 화면에 예산 막대 추가` · 나쁜 예: `수정`

### ④ 올리기 (Push)

위쪽 **Push origin** 클릭. 이제 팀원들이 받을 수 있습니다.

> **작게 자주 올리세요.** 1~2시간마다 한 번. 하루 모아서 올리면 충돌이 커집니다.

## 문제가 생겼을 때

### Push가 안 되고 "Pull 먼저 하라"고 할 때

다른 사람이 먼저 올린 것입니다. **Pull origin**을 누른 뒤 다시 **Push origin**.

### 충돌(conflict)이 났을 때

같은 파일의 같은 부분을 두 사람이 고친 것입니다.

1. 당황하지 말고 단톡방에 알리기
2. 파일을 열면 이런 표시가 있습니다.
   ```
   <<<<<<< HEAD
   내가 쓴 내용
   =======
   팀원이 쓴 내용
   >>>>>>> ...
   ```
3. 둘 중 맞는 것만 남기고 `<<<<<<<`, `=======`, `>>>>>>>` 줄을 모두 지운 뒤 저장
4. GitHub Desktop에서 Commit → Push

### 망한 것 같을 때

**절대 폴더를 지우고 새로 받지 마세요.** 올리지 않은 작업이 사라집니다. 먼저 단톡방에 화면 캡처를 올리세요.
